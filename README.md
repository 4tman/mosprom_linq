# Пост контроля безопасности

Прототип операторской панели для кейса «Контроль нарушений промышленной
безопасности по видео с камер на ускорителях LinQ».

Панель показывает: обработанный кадр с разметкой, состояние зоны, метрики
обработки и журнал событий с кадрами-доказательствами и фильтрами
(тип, камера, зона, даты) — как требует задание.

## Запуск

```bash
pip install -r requirements.txt
python -m streamlit run app.py
```

Проверка логики без интерфейса:

```bash
python tests/test_smoke.py
```

## Структура (4 файла + тесты)

| Файл | Ответственность |
|---|---|
| `app.py` | Только интерфейс Streamlit: кнопки, кадр, метрики, журнал |
| `processor.py` | Источники кадров и «детекторы»: демо и LinQ (preprocess/postprocess) |
| `linq_client.py` | Транспорт к сервису инференса LinQ через RabbitMQ (заполнить LinQConfig) |
| `events.py` | Чистая логика: подтверждение нарушения во времени и подавление повторов |
| `storage.py` | Журнал SQLite + кадры-доказательства |
| `stand_check.py` | Проверка инференса LinQ: запуск с локалки, подключение напрямую к RabbitMQ (VPN) |
| `tests/test_smoke.py` | Проверки логики: 11 сценариев |

Поток данных:

```
processor (кадр + детекции) → events (событие?) → storage (журнал) → app (оператору)
```

## Честная пометка про демо

Сейчас по умолчанию работает **демо-режим**: детекции скриптовые
(человек «идёт» по синтетической сцене), реальное видео не анализируется.
Это сделано намеренно — сначала интерфейс и логика событий, затем реальная
модель. Панель честно предупреждает об этом режиме.

## Подключение LinQ (текущий этап)

1. **Проверка связи**: скопируйте `stand_check.py` и `linq_client.py` в Jupyter
   на стенде, впишите свой логин в `LinQConfig`, запускайте `stand_check.py` —
   он проверит один инференс и замерит задержку на 10 запросах.
2. **Модель**: получите `.tpu`-программу детектора (вопрос к организаторам:
   как компилировать свою модель), положите в `/auto/cache/<логин>/`.
3. **LinQConfig** в `linq_client.py`: логин, имя `.tpu`, имена входного/
   выходного тензоров, форма входа.
4. **preprocess / postprocess** в `LinQBackend` (`processor.py`):
   кадр → тензор и выход → detection-словари по контракту из шапки файла.

После этого в панели выберите «Обработчик → LinQ» — остальная система
(события, журнал, доказательства) уже готова и протестирована.

Важно: имена функций `tpu_pycloud_format` сверьте со скачанным
`example.ipynb` — места сверки помечены в `linq_client.py`.

## Ограничения текущей версии (говорим честно)

- один трекер = одна камера, одна зона, один тип нарушения;
- трекинг людей (track_id) не подключён — событие на «эпизод зоны»,
  а не на конкретного человека;
- LinQ-бэкенд — заготовка.

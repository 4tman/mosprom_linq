# Пост контроля безопасности

Прототип операторской панели для кейса «Контроль нарушений промышленной безопасности по видео с камер на ускорителях LinQ».

Панель принимает кадры (видео или фотографию), отправляет их на нейросетевой детектор, который работает **на ускорителе LinQ**, и показывает оператору найденные объекты: людей, каски, жилеты и их отсутствие. Для видео поверх детекций работает логика подтверждения нарушений и журнал событий с кадрами-доказательствами.

Команда «Мясокомбинат».

## Возможности

- **Фото → LinQ → результат.** Загружаешь фотографию, получаешь рамки, классы, уверенность, задержку запроса и служебный ответ воркера LinQ. Результат можно сохранить (`original.jpg`, `annotated.jpg`, `result.json`).
- **Видеорежим.** Источник кадров — синтетическая сцена или видеофайл. На кадре задаётся запрещённая зона. Нарушение подтверждается во времени (одиночный кадр не считается нарушением), повторы подавляются.
- **Журнал событий.** SQLite-журнал с кадрами-доказательствами и фильтрами по типу, камере, зоне и датам.
- **Честный демо-режим.** `DemoBackend` рисует скриптовые детекции для отладки интерфейса, и панель явно помечает этот режим. Реальные результаты даёт только `LinQBackend`.

## Как это работает

```text
app.py (Streamlit)
  └─ image_panel.py / видеорежим
       └─ processor.py · LinQBackend
            ├─ letterbox(): кадр → тензор 1×3×640×640, float32, 0..1
            ├─ linq_client.py → RabbitMQ (pika) → стенд LinQ
            │                     └─ safetyvision_linq.tpu → output0 (1, 17, 8400)
            └─ decode_yolov8(): фильтр по уверенности + NMS → рамки в пикселях кадра
       └─ events.py (подтверждение нарушения) → storage.py (журнал) → оператору
```

Модель на ноутбуке не запускается: в коде нет `torch`, `ultralytics` или `onnxruntime`. Нейросеть выполняется только на стенде LinQ, а ноутбук готовит кадр, отправляет его и разбирает ответ.

## Структура репозитория

| Файл | Назначение |
|---|---|
| `app.py` | Точка входа: интерфейс Streamlit |
| `image_panel.py` | Раздел «Фотография → LinQ → результат» |
| `processor.py` | Источники кадров, `DemoBackend`, `LinQBackend` (подготовка входа и разбор выхода YOLOv8), отрисовка рамок |
| `linq_client.py` | Транспорт к стенду: задача в RabbitMQ, ожидание ответа, `LinQConfig` |
| `events.py` | Чистая логика: попадание в зону, подтверждение во времени, подавление повторов |
| `storage.py` | Журнал SQLite и кадры-доказательства |
| `check_safetyvision.py` | Проверка без интерфейса: одно фото → LinQ → сырой `output0` |
| `build_safetyvision.py` | Сборка `.tpu` из ONNX через SDK LinQ (квантование на фото из `calibration/`) |
| `build/model_info.json` | Описание собранной модели: имена и формы тензоров |
| `class_names.json` | Имена 13 классов в порядке модели |
| `test_smoke.py` | Проверки логики событий без интерфейса |
| `requirements.txt` | Зависимости Python |

В репозиторий не входят (см. `.gitignore`): виртуальные окружения, SDK организаторов (`tpu_sdk/`), веса моделей (`*.onnx`, `*.tpu`), калибровочные фотографии и папка `data/`.

## Модель

- Детектор: [SafetyVision YOLOv8](https://huggingface.co/ayushgupta7777/safetyvision-yolov8), 13 классов СИЗ, лицензия AGPL-3.0.
- Вход: `images`, `(1, 3, 640, 640)`, `float32`, RGB, значения 0..1, вписывание с серыми полями `114`.
- Выход: `output0`, `(1, 17, 8400)` — 4 координаты рамки (`cx, cy, w, h` в пикселях входа 640) и 13 оценок классов для 8400 кандидатов.
- Скомпилированная программа: `safetyvision_linq.tpu`, лежит на стенде в `/auto/cache/<логин>/`.

Классы (`class_names.json`):

```json
["Fall-Detected", "Gloves", "Goggles", "Hardhat", "Mask",
 "NO-Gloves", "NO-Goggles", "NO-Hardhat", "NO-Mask",
 "NO-Safety Vest", "No_Harness", "Person", "Safety Vest"]
```

## Требования

- Linux (проверено на Ubuntu), Python 3.12.
- VPN-доступ к сети стенда LinQ (брокер RabbitMQ стенда).
- Логин на стенде и загруженная туда программа `.tpu`.
- Модуль `tpu_pycloud_format` (формат сообщений LinQ) от организаторов — его импортирует `linq_client.py`. Положи папку в корень проекта.
- Только для сборки модели: SDK LinQ (`tpu_sdk/`, колёса `.whl`) от организаторов.

## Установка

```bash
git clone <адрес-репозитория> safety_panel
cd safety_panel

# окружение (через uv; можно и python -m venv)
uv venv --python 3.12 .venv-linq
uv pip install --python .venv-linq/bin/python -r requirements.txt

# проверка, что всё на месте
.venv-linq/bin/python -c "import streamlit, cv2, PIL, numpy, pika, tpu_pycloud_format; print('OK')"
```

Важно: ставь пакеты именно в `.venv-linq` (через `--python .venv-linq/bin/python`). Обычный `pip` может поставить их в `~/.local`, и тогда при запуске будет `ModuleNotFoundError`.

## Настройка

Параметры подключения задаются в `default_linq_config()` в `processor.py`:

```python
LinQConfig(
    login="<ваш_логин>",              # логин на стенде
    program="safetyvision_linq.tpu",  # имя программы в /auto/cache/<логин>/
    input_tensor_name="images",
    output_tensor_name="output0",
    input_shape=(1, 3, 640, 640),
    dtype="float32",
    request_timeout_s=120,
)
```

Адрес брокера (`host`, `port`) задан в `LinQConfig` в `linq_client.py`. Пароли и токены в код не пишем: если они понадобятся, выносим их в переменные окружения или `.env` (он в `.gitignore`).

## Использование

### 1. Проверка связи со стендом

```bash
.venv-linq/bin/python -u check_safetyvision.py
```

Скрипт берёт первое фото из `calibration/`, отправляет его на LinQ и печатает ответ. Ожидаемый результат:

```text
Воркер: {'worker_pid': '6', 'thread_name': 'Worker Thread #1', 'inference_time': 0.0066, 'status_code': 0, ...}
Выход: (1, 17, 8400) float32
Все значения конечные: True
ОТВЕТ LinQ ПОЛУЧЕН И СОХРАНЁН
```

### 2. Запуск панели

```bash
.venv-linq/bin/python -m streamlit run app.py
```

Откроется `http://localhost:8501`.

- **Фотография:** раздел «Фотография → LinQ → результат» → загрузи JPG/PNG → «Обработать на LinQ» → «Сохранить результат».
- **Видео:** в боковой панели выбери источник кадров (синтетика или видеофайл) и обработчик «LinQ» → «Начать». События появятся в журнале внизу.

Порог уверенности и NMS можно менять при создании бэкенда: `LinQBackend(confidence_threshold=0.4, iou_threshold=0.45)`.

### 3. Тесты логики

```bash
.venv-linq/bin/python test_smoke.py
```

### 4. Сборка своей модели (необязательно)

Нужно, только если меняешь модель.

1. Установи колёса SDK из `tpu_sdk/` в `.venv-linq`.
2. Положи 5–20 фото в `calibration/` — они нужны для квантования.
3. Запусти сборку:
   ```bash
   .venv-linq/bin/python -u build_safetyvision.py 2>&1 | tee build_safetyvision.log
   ```
4. Получишь `build/safetyvision_linq.tpu` и `build/model_info.json`.
5. Загрузи `.tpu` в Jupyter на стенде и скопируй в `/auto/cache/<логин>/`.
6. Сверь имена и формы тензоров в `model_info.json` с `LinQConfig`.

## Как убедиться, что работал LinQ

- В панели и в `result.json` есть ответ воркера (`worker_pid`, `thread_name`, `inference_time`, `status_code`). Эти поля приходят только со стенда.
- `inference_time` (≈ 6–7 мс) — расчёт на ускорителе. Задержка запроса (1–3 с) — полный путь через сеть и очередь. Это разные величины.
- Без VPN или с неверным именем программы панель выдаёт ошибку и не рисует рамок: подмены на демо нет.
- `rg -n "ultralytics|onnxruntime|torch" *.py` ничего не находит: локальной модели нет.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `No module named 'pika'` / `'streamlit'` | Пакет стоит в другом окружении. Ставь так: `uv pip install --python .venv-linq/bin/python <пакет>` |
| `No module named 'tpu_pycloud_format'` | Нет модуля от организаторов: положи папку в корень проекта |
| Таймаут ответа воркера | Нет VPN, неверный логин или программы нет в `/auto/cache/<логин>/` |
| Подписи `class_0`…`class_12` | Нет `class_names.json` или в нём не 13 имён |
| Рамки сдвинуты | Подготовка кадра не совпадает со сборкой: проверь `letterbox()` и `model_info.json` |

## Ограничения

- Одна фотография не подтверждает нарушение во времени: это делает только видеорежим.
- Одно правило — одна камера, одна зона, один тип нарушения. Трекинг людей (`track_id`) не подключён.
- Качество классов у модели неодинаковое: например, `NO-Safety Vest` распознаётся слабее остальных.
- Задержка запроса определяется сетью и очередью, а не скоростью ускорителя.
